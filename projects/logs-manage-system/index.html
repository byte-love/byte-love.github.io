日志管理与账号运维后台

跨 4 个生产 MongoDB 库、3 台 SQL Server 的只读运维后台，单人主力全栈。

角色
服务端 + 前端（主力，63% 提交）
时间
2026.08 – 2026.09
技术栈
Spring Boot 2.7 · Vue 3 · MongoDB · SQL Server · Apache POI · WebSocket
仓库
github.com/byte-love/logs-manage-system

问题

账号数据和操作日志分散在多套历史库：两张日志源表的 _id 各自从 1 开始自增、值域完全重叠，合并写入会逐条覆盖 188 万条真实记录；同步断点书签停在 563 万而目标已到 2250 万，按陈旧书签会重复拉 1690 万行；SQL Server 定长 CHAR 迁过来的机构名带尾填充空格，等值查询恒不命中。

我做的

  • 把两张日志表拆成两个独立集合，并写下「禁止合并 / 禁止加偏移」两条铁律
  • 给同步加断点自愈：先用形状校验（缺失字段计数 = 0）证明可安全抬升书签，再自动推进
  • Excel 导出改为全流式：SXSSF 200 行滑窗 + 服务端游标 + 预载邮箱映射，替掉全量驻留内存的写法
  • 机构匹配改用锚定正则 ^\s*值\s*$，三个查询入口共用同一个条件构造器
  • 接入中英文日志表（En_Log）增量同步，按源文档 ObjectId 做断点，补语言版本列

结果

  • 待拉行数 1690 万 → 74,912（225 倍）
  • 导出 12.98 万行 / 24 秒 / 11 MB，44,968 个材料链接全部补上
  • 机构筛选命中 4185 → 5525 条（找回整批被静默漏掉的学校账号）
  • 9 个测试类 73 个用例，全 Mock，不连库不连源
